Draft implementation sequence — 2026-11-23

1. M0: Verify both ACP worker routes in isolated fixtures. Resolve whether ChatGPT means Codex or the app. Record versions, authentication, streaming, cancellation, permissions and resume capability.
2. M1: Build one supervised task end to end. Keep provider transport behind a small adapter and enforce chosen permissions outside the model. Begin with one worker per workspace.
3. M2: Add scoped durable conversation memory and bounded handoff context. Separate user preferences, project facts, summaries, task state and planning records.
4. M3: Persist worker lifecycle, reconcile interruptions, prevent duplicate dispatch, bound retries and report evidence. Do not blindly replay unknown side effects.
5. M4: Add plantool operations, bounded lookups and inspectable Agent Skills. Reuse worker-native tooling.
6. M5: Run deterministic failure tests, opt-in live tests and a short user pilot before expanding.

Architecture proposal: interaction surface -> Mastra supervisor -> bounded tools and worker adapter -> Cursor / confirmed OpenAI worker. Context assembly and permission enforcement are explicit application services. A runtime store holds conversation and task state. plantool .plan holds goals, decisions and planned/completed work. No separate orchestration platform is needed for this first loop.

Review order: top-level goal, five open decisions, M0 compatibility tasks, then milestone acceptance criteria and dependencies. Ticket dependencies control readiness; open person-owned choices block only affected work. Future candidates are labelled later,not-mvp and wait for the pilot.

Current evidence: Cursor CLI 2026.11.17-f532c45 exposes agent acp. Installed Codex is 0.171.0-alpha.13. These are local version/help checks only, not authenticated integration results. Official Cursor docs describe native ACP; the maintained Codex ACP adapter describes a Codex App Server bridge with ChatGPT login. Direct ChatGPT-app ACP support is unverified. Pin actual tested versions during M0.
